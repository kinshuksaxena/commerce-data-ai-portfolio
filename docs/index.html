Architectural Tenets

  • Strict Database Isolation: The transactional PostgreSQL engine enforces domain isolation across schemas: catalog, orders, delivery, customers, and inventory. Monolithic joins across unrelated domains are forbidden.
  • Asynchronous Pub/Sub Mesh: High-velocity events (driver GPS breadcrumbs, inventory adjustments, status webhooks) stream through Google Cloud Pub/Sub topics.
  • Hot vs. Cold Separation: High-frequency GPS coordinates flow directly to Google Cloud Bigtable for ultra-fast time-series analytics, while stateful transitions land in PostgreSQL for driver logistics.

Step 01 • 10s Windowing
Fixed Window Aggregation
GPS coordinates arrive every second. Apache Beam groups pings into deterministic 10-second tumbling windows per route to eliminate telemetry jitter and smooth out speed anomalies.
Step 02 • 550m Geofencing
Spatial Proximity Check
When a vehicle moves within ±0.005° (≈550m) of an assigned customer stop, the streaming worker flags an imminent arrival and triggers the webhook delivery worker.
Step 03 • 30s Package Drop
Stop Dwell Simulation
To mirror physical human drop-offs, the telemetry engine pauses the vehicle at each delivery coordinate for a 30-second dwell period before continuing the route loop.

High-Throughput Inventory Mesh & Pessimistic Locks

How to avoid overselling during intense checkout spikes without degrading read latency for millions of browsing shoppers.

Blueprint 03 Autonomous Warehouse Publisher & 3-Stage ACID Concurrency Pipeline
Auto-Discovery Row Lock ACID Redis L1 Sync
Warehouse Simulator Auto-Discovery
Polls catalog.product_catalog for live SKUs & fires emergency RESTOCK events when safety-stock thresholds breach.
Publish Delta
Cloud Pub/Sub Topic inventory-updates
High-throughput topic ordering stock adjustments, restocks, and warehouse cycle counts.
Beam Pull
Apache Beam Subscriber inventory-beam-sub
Executes deterministic 3-step transactional stock mutation & L1 cache synchronization.
1. Idempotency Guard Deduplication
Verifies event UUID against inventory.processed_inventory_events before mutation to guarantee exactly-once processing across Beam retries.
2. Pessimistic Row Lock SELECT ... FOR UPDATE
Acquires row-level lock on inventory.inventory_levels, prevents negative stock drift, and appends to immutable inventory.inventory_audit_log.
3. Sub-ms L1 Cache Sync Redis 7 + DLQ
Atomically updates Redis 7 keys stock:{product_id} & stock_total:{product_id}, routing any schema violations to the DLQ quarantine side-output.

Multi-Level Concurrency Architecture

When orders surge, naive architectures face race conditions where two simultaneous transactions claim the final remaining unit. We designed a dual-tier protection layer:

Tier 1: Redis Fast Cache

Provides sub-millisecond stock availability checks for product catalog browse queries without hitting the database disk.

Tier 2: Pessimistic Row Lock

SELECT ... FOR UPDATE locks only the specific SKU during checkout, serializing deductions with zero risk of negative balances.

Tier 3: Dead Letter Queue (DLQ)

Malformed stock adjustment messages automatically route to a dead-letter queue after 3 retries, preserving stream liveness.

Chapter 06

Automated Orchestration with Apache Airflow

Zero-downtime, deterministic DAG orchestration syncing transaction dumps, executing dbt transforms, and driving Reverse-ETL sync loops.

Production Airflow DAG Fleet

  • dag_periodic_orders_export: Executes every 30 minutes. Dumps newly completed orders from PostgreSQL into Bronze Avro partitions in GCS with millisecond watermarks to prevent duplicate ingestion.
  • dag_dimension_ingestion: Ingests slow-moving customer profiles and product catalog snapshots to maintain fresh dimensional lookups in the warehouse.
  • dag_reverse_etl_sync: Queries BigQuery Gold data marts for product popularity indices and syncs them back to the operational database with transactional upserts.
